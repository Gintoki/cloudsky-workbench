# 公司研究系统重构计划

## 1. 当前状态

### 技术与架构

- 前端为 Next.js 16 / React 19 / TypeScript，使用 Vinext 构建；现有工作台采用 Server Page + Client View 的模式。
- 样式以项目现有全局 CSS 和工作台基础组件为主；不新增组件库或替换技术栈。
- 持久化层为 PostgreSQL + Drizzle ORM。API 使用 Next Route Handlers、Zod 校验、RBAC 和审计日志。
- 当前导航中的“公司研究”实际指向 `/intelligence`。该页面是行业动态列表，并非公司档案或研究框架。

### 可复用资产

- `companies`、`securities`、`stock_prices`、`financial_statements` 可作为公司、代码、行情和报表的权威记录。
- `industries`、`intelligence_items`、`intelligence_item_companies` 已能将行业动态与公司关联；公司研究只读取并引用这些动态，不复制一份新闻。
- `sources`、`document_chunks`、`citations`、`company_facts` / `fact_sources` 已提供来源、引文和通用事实能力。
- `valuation_models`、`valuation_assumptions`、`valuation_results` 保留为现有估值模型底座；研究报告通过关联引用，不重复计算其结果。
- `content_status`、角色权限、`audit_logs`、现有页面状态组件和工作台壳层可继续使用。

### 当前不足

- 没有以公司为中心的研究报告、章节、假设、护城河、风险、监控项、估值情景或版本快照。
- `company_facts` 和 `metrics` 均不带 `company_id`，不适合作为完整公司研究工作区的主表。
- 历史公司字段 `internal_conclusion`、`watch_rationale`、`risk_factors` 缺少版本、来源分类和可审核结构。
- 现有公司研究与行业动态混用，导致“动态”和“深度判断”界限不清。

## 2. PDF 方法论提炼

PDF 被用作方法论来源而非实时数据源。其可复用原则为：

1. 先定义当前判断、能力圈边界、核心矛盾和结论置信度，再讨论细节。
2. 把投资观点拆成少量可证伪的关键假设；每项同时记录支持证据、反证、验证指标、失效条件和复查日期。
3. 将行业特征、公司 Alpha 和竞争壁垒分开分析，避免将景气误判为公司能力。
4. 护城河必须区分暂时性技术领先、需要持续投入维持的优势与结构性优势，并记录其趋势和失效条件。
5. 财务质量、现金转换、资本回报、负债安全性和正常化利润不能被单一增速或利润数字替代。
6. 估值方法应匹配商业模式，并使用情景和敏感性表达不确定性；缺乏可靠输入时明确“暂时无法估值”。
7. 风险、反方观点、催化剂与监控指标应并列呈现；好公司与好价格分开判断。
8. 任何事实、预测、推断、观点和未知项必须明确分类、来源、数据期间和时效。

方法论本身将作为带来源、页码/定位、录入时间与核验状态的通用事实入库。PDF 中的具体公司案例、历史估值、价格和未经复核结论不迁入生产公司档案。

## 3. 新信息架构

### 页面与路由

- `/company-research`：公司研究列表，显示研究状态和可进入的公司档案。
- `/company-research/[companyId]`：结构化研究工作台。
- 行业动态仍在 `/intelligence`；研究工作台底部只展示已关联公司的最新动态和原始链接。

### 工作台层级

顶部摘要：公司、Ticker、行业、更新时间、判断、置信度、核心矛盾、估值状态、完整度、版本变化。

章节导航：总览、商业模式、核心假设、行业与竞争、护城河、管理层与治理、财务质量、估值、催化剂与风险、监控指标、信息来源、历史版本。

每个章节使用结构化记录优先、可编辑文本补充的方式，避免形成一篇不可维护的长报告。

## 4. 数据模型方案

新增表遵循现有 `research_*` 命名，并保留 `company_id`、组织隔离、状态、来源和审计关联。

| 实体 | 用途 | 关键关系 |
| --- | --- | --- |
| `research_reports` | 每家公司一份当前研究档案和顶层结论 | 公司、组织、负责人、审核人 |
| `research_sections` | 可编辑章节内容及其事实/观点分类 | 报告 |
| `research_assumptions` | 3-7 条可验证投资假设 | 报告、负责人 |
| `research_moats` | 分维度护城河与趋势、证据和反证 | 报告 |
| `research_metrics` | 公司研究专用指标，支持 Actual/Budget/Forecast、正常化和异常解释 | 报告、来源、报表 |
| `research_valuations` | 方法、当前价格日期、情景、价值区间、敏感项 | 报告、现有估值模型 |
| `research_observations` | 催化剂、风险、反方观点、监控项 | 报告 |
| `research_claims` / `research_claim_sources` | 细粒度 Fact/Estimate/Inference/Opinion/Unknown 与多来源证据 | 报告、章节、来源 |
| `research_versions` | 不可变快照与变更摘要 | 报告、创建人 |
| `research_reviews` | 提交、审核、驳回记录 | 报告、版本、审核人 |
| `research_industry_modules` | 可配置行业插件和指标定义 JSON | 报告按模块代码加载 |

行业插件预置 AI Infra、半导体、消费/IP、游戏、SaaS、制造业、白酒及渠道消费。前端读取模块配置渲染标签、提示和指标，不为行业规则写 if/else 分支。

## 5. 页面结构方案

1. 列表页使用紧凑表格：公司、行业、当前判断、核心矛盾、更新时间、完整度、假设状态、估值状态、风险触发、负责人。
2. 详情页先显示真实摘要和状态；不存在报告时只显示“待建立”，不填充模拟数据。
3. 章节采用左侧标签 + 右侧工作面；可编辑章节提供保存草稿，假设提供新增/修改/状态更新。
4. 提交审核与批准仅在对应权限下显示并调用真实状态变更 API。
5. 来源页显示分类、来源日期、数据期间、引用摘录和核验状态；过期内容标记而不改写其原始值。
6. 版本页读取不可变快照，并提供相邻版本的变更摘要。

## 6. 迁移方案

1. 迁移只新增表、索引、枚举与外键；不删除、不改写现有公司、动态、估值或报表表。
2. 对已有 `companies`：若 `internal_conclusion`、`watch_rationale`、`risk_factors` 有内容，则幂等创建草稿研究档案及对应章节。
3. 旧字段生成的章节标为“待人工整理”，保留原文，且不覆盖之后的人工修改。
4. 关联动态继续通过 `intelligence_item_companies` 查询；不复制 `intelligence_items`。
5. PDF 方法论由显式、可重复运行的导入脚本写入通用事实库，并引用“投资方法框架”来源；不会批量导入案例公司的数据。
6. 回滚方式：迁移文件提供对应的表删除顺序和数据导出说明；生产执行前备份新增表。现有表未被修改，因此可独立恢复。

## 7. 实施步骤

1. 建立本计划、Skill、研究模板和数据质量规则。
2. 新增研究数据模型、Drizzle 迁移、权限和幂等旧数据迁移。
3. 实现研究仓库、输入校验、读写/提交/审核 API 与审计日志。
4. 增加公司研究列表、详情工作台、可编辑章节与假设、关联行业动态、版本/来源视图。
5. 将侧边栏“公司研究”连接到新路由；保留行业动态入口不变。
6. 补齐单元测试，执行类型检查、lint、迁移生成/校验、构建和相关端到端测试。

## 8. 风险

- PDF 是案例型材料，不能把其中的证券价格、估值或观点当作当前事实；只导入通用方法论。
- 现有公司字段可能是自由文本，自动映射需始终标记待人工整理。
- 数据库未配置时不能持久化；UI 必须明确显示数据接入状态而非伪造研究记录。
- 历史估值模型目前未强制关联公司，研究页只引用明确关联的数据，避免错误归属。
- 研究结论涉及权限与审批，写操作必须通过服务端授权并留下审计记录。

## 9. 验收标准

- 可基于已有公司创建研究档案，且可编辑、保存、提交与审核。
- 旧公司内容迁移后保留原文并可重复执行，不覆盖人工研究。
- 每家公司可加载行业模块配置与对应指标定义。
- 重要内容可使用 Fact、Estimate、Inference、Opinion、Unknown 分类，并关联来源和数据时效。
- 可创建、更新、查看假设的支持/反对证据、失效条件和下次检查日期。
- 可查看版本快照、审核记录及关联行业动态。
- 无数据时显示“暂无数据/待接入”，不显示 0 或模拟金额。
- 既有 `/intelligence`、公司/动态关联、权限和其他路由不受影响。
- lint、typecheck、build 和覆盖本改动的测试通过。
