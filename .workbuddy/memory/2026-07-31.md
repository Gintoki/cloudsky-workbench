## 公网部署 → Render（CF 路线放弃）

**CF 路线放弃的原因**：
- `vite.config.ts` 虽 import `@cloudflare/vite-plugin`，但 **build 产出的是标准 Node server**（`dist/server/index.js`），不是 CF Worker bundle
- `.wrangler/` 无 worker 产物，无 `wrangler.toml`
- CF 插件只用于 dev 时 miniflare 模拟，build 不产出 CF 部署产物
- 要上 CF 得额外造 wrangler.toml + 改 build 流程 + 解决 Workers 连 PG，不确定性高

**Build 踩坑（已修复）**：
- `build/sites-vite-plugin.ts` 的 closeBundle 用 `fs.rm(recursive:true)` 清理 `dist/.openai`，被 WorkBuddy 沙箱 safe-delete shim 拦截 → build 5 步只跑 2 步就中断
- **修复**：把 `rm` 包 try/catch 容错（失败继续，mkdir recursive 不受影响）→ build 5 步全跑完，21 条路由产物齐全，`dist/` 2.6M

**vinext start 兼容性（关键）**：
- `vinext start` 支持 `-p, --port`，默认读 `PORT` env，fallback 3000
- `-H, --hostname` 默认 0.0.0.0（已是 Render 需要的）
- **Dockerfile 不用改**：Render 注入 `PORT` env，vinext 自动监听
